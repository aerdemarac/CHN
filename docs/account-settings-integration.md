# Account Settings frontend

`account-settings.php` is a single root-level visual preview for patient, doctor, healthcare_staff and admin. Open `http://localhost/CHN/account-settings.php?role=patient`. Missing, invalid and array roles default to patient. URL role selects fictional presentation only; it never authenticates or authorizes. No sessions, cookies, account reads, network mutation calls, storage or database changes were added. A manually forged POST renders a no-changes notice and ignores submitted values.

The existing Top Bar discovers the root file automatically. Its account link now retains supported canonical role labels, and its title map includes Account Settings. Its layout/interactions and the Sidebar are reused. Admin sidebar settings.php remains separate. Medical Cases, Feedback and Dashboard code are untouched.

Personal information uses user schema names name, surname, email, phone, birth_date, gender and nationality. Required names/email and optional international phone, non-future birth date and two-letter nationality code are checked in the browser. Invalid fields get adjacent errors, aria-invalid and focus on the first failing control. National ID, internal IDs, passwords and hashes are not displayed. Role is display-only. Fixtures use example.invalid; do not enter real personal information.

Preferred languages reuse the actual Top Bar language map and order (tr/en/el/ru/yo/de/fr/es). Notification choices are illustrative draft controls; they do not imply delivery or existing preference columns. Theme remains light. Checking a draft reports that nothing is saved; Save and Change Password are unavailable. No password fields are requested without a secure workflow. Cancel restores all fictional form defaults and clears errors. Changed drafts trigger the browser's native leave/reload warning, when supported; successful validation does not mark drafts as saved. No-JavaScript submission buttons stay disabled.

Future integration requires verified account reads, an authenticated update interface, server-side validation and email uniqueness/verification policy, CSRF and appropriate account authorization, country/gender normalization, and a separately approved preferences storage contract (not currently in user schema). Identity and role must come from trusted authentication, never GET or editable form fields. A real password workflow requires current-password verification/reauthentication, server hashing and session handling. Replace draft-only interactions only once these contracts exist. No endpoint or database migration was invented.

Verification: browser checks passed for all four roles at 393px, 768px and 1440px (12 combinations): no horizontal overflow, existing shell preserved, Profile dropdown/account link, exact language order, invalid email/phone messages and first-error focus, valid draft prevention of submission, reset and dirty-state feedback. No fetch/XHR calls were made. The temporary browser harness was removed. PHP syntax passed for the page and modified Top Bar; referenced local page/shell assets exist; git diff --check passed. Only the new page, its scoped CSS/JS/documentation and the Account Settings link/title in Top Bar were changed. No assets were downloaded.
