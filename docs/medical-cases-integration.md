# Medical Cases integration

`medical-cases.php` is an explicitly labeled frontend preview, using only `include/medical-cases-preview-data.php`. No database connection, working authentication/session contract, case API, or diagnosis API exists in this checkout. README backend filenames describe planned files. No live request or automatic demo fallback is implemented. No diagnoses are fabricated and there is no separate diagnosis page.

The schema defines `patient`, `doctor`, `staff`, `admin`. The Sidebar currently has one unconditional navigation list, with no role definitions or role filtering. “Healthcare Staff” maps to database `staff`; the top bar's role is only a display label. No shared permissions or navigation have been changed. Admin access must be specified by the backend team, not inferred.

Before enabling live records, replace the fixture loading with the team's documented authenticated read interface and remove the preview labels/DEMO prefix. Do not expose an unrestricted dataset and filter it in the browser. Enforce patient ownership through patient.user_id; enforce the backend team's authorized doctor assignment and staff hospital/department scope on both list and individual case/diagnosis requests. Fail closed for unauthenticated, unsupported-role and unassigned accounts. Recheck every supplied case ID; GET parameters are untrusted. Do not infer broader departmental access for doctors or any admin clinical access from role labels. Counts and department options must come only from the authorized scope. Specify pagination and count semantics with the backend if lists are paginated.

The current view uses schema fields case_id, department_id, case_description, case_state, tier_color, created_at and joined department_name/doctor_name display fields. `open` is labeled Active; `closed` is Closed. Triage remains orange/yellow/green and does not determine case state. Orange/yellow use the design palette's shared warning color with distinct shapes and explicit text labels.

Diagnosis history accepts zero or more records with diagnosis_id, case_id, diagnosis_text, diagnosed_at, optional icd_code and optional joined doctor_name. Join diagnosis.case_id to case.case_id and diagnosis.doctor_id to doctor/user independently of the case's responsible doctor. Render newest first; escape all output. Missing diagnoses, doctor, ICD and case description are supported. Agree date/time timezone semantics with the backend (schema DATETIME has no timezone). No mutation actions are provided.

Filters use GET q/status/department; selection uses GET case and preserves the active filters. Selection is resolved only within the current results; changing filters clears selection. The page operates without feature-specific JavaScript and reuses the existing sidebar/topbar scripts.
